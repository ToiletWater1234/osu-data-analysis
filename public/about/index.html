使用方法

点击右上角“使用 osu! 登录”，在 osu! 官网完成授权。浏览器已有 osu! 登录状态时可沿用该状态；首次使用仍需确认授权。本站不会要求输入 osu! 密码。

BP 分析
输入玩家名或数字 ID，选择游戏模式；mania 可选择 4K、7K 或全部键数。未登录时示例为 MyAngelHyacine / 35851725，登录后使用自己的信息。系统读取公开 BP 与置顶成绩，生成玩家画像。mania 的完整谱面分析需要等待下载和计算完成。
玩家对比
输入两位玩家的数字 ID，在同一游戏模式及键数范围下并列查看表现。此页面比较各自的成绩样本，并非相同谱面的逐图对战。
谱面查询
输入歌名、单张谱面的数字 ID，或包含难度 ID 的官网链接，例如 osu.ppy.sh/beatmaps/123。谱包链接请带上具体难度的锚点；搜索结果可跳转 osu! 官网。官网检索包含 Loved、坟图等状态；切换“本地谱面”可查询已绑定的 Songs，无需登录。本地检索只展示文件信息，不计算难度。

首页轮播下方的“图PP列表”并列提供 mania 4K 图 PP 表格 与 CTB 图 PP 表格，点击后在新标签页打开腾讯文档。

三个工具拥有独立页面，可直接收藏链接。谱面查询的官网结果会自动识别每个难度的模式：mania 复用原版七列格式、Mod 选项与星数分页提示，CTB 使用新八列格式。不另设 CTB pp 图表页面；标准模式、太鼓和本地检索暂不提供格式生成。谱面 ID 及带难度的官网链接只展示对应难度，完整谱包链接也可查询。

在对应难度下展开“生成表格格式”，选择 Mod 后生成并复制。CTB 模组用勾选框多选，空选为 NM；EZ 与 HR 不能同时选，DT / NC / HT 三者互斥，前端禁用并在后端复核。完整组合提交 官方难度接口，明确使用谱面实际 ruleset，不用单模组星数或固定倍数拼接。官方 CTB 计算实现主要考虑 EZ、HR 和变速模组；NC 使用 DT 的速度。HD、FL 一并记录和提交，但不假设它们必定改变星数。当前仅支持 EZ、HD、HR、DT、NC、HT、FL 的默认设置，不支持自定义变速或 lazer 专用调整模组。

CTB 前七列为 ID、名字、难度、星数(mod后)、时长(mod后)、bpm(mod后)、模组，第八列为玩家评价；NM 的模组格留空。字体与边框沿用定稿 XLSX 的微软雅黑 18 磅居中样式。按最新要求，正文单元格无填充色，取消白 / 浅蓝交替和评价标黄，仅保留星数格的难度色，统一一个复制按钮。即使评价不填，仍保留第八个空白单元格，不自动编写评价。页面预览的白色底板仅用于阅读，不写入复制内容。CTB 星数向下截断到两位，mania 沿用原版两位四舍五入。时长是文本“分:秒”，DT / NC 按 1.5 倍、HT 按 0.75 倍换算 BPM 和时长。

CTB 的 ID 为数值型整数，数字格式为 0，不带小数或分隔符；单元格及官网链接文字均使用蓝色 #0073A7，保留官网跳转。复制时明确声明为数字，不是文本或公式；时长则仍独立声明为文本“分:秒”。旧版字符串 ID 的表格行也会在复制前转换为整数，mania 原版 ID 格式不变。

富文本复制需要 HTTPS 或 localhost、浏览器剪贴板权限及支持 HTML 的目标表格；若退回纯文本，会明确提示不含底色、字体与边框，时长使用表格文本前缀避免误识别为“时:分”。本页评价草稿仅保存在当前页面内存，不上传服务器，刷新即清空。生成的是谱面收集格式，不是成绩 PP 预测，不自动改写腾讯文档；官网接口失败时不猜测 Mod 后星数。表格行使用短期 Cache API 缓存最多一小时，不新增持久 KV 写入；登录仍使用既有 OAuth 会话，凭据设置未改动。

分析范围与结果含义

无论是否绑定本地目录，基础画像始终使用 B50。目录已绑定且可读取时，mania 额外从有实际成绩的 Loved / 坟图中，选取成绩 PP 最高的最多 50 张谱面参与键型与 RC / LN 能力分析。额外样本不足 50 张时按实际数量处理；与 B50 重复的谱面不重复计入。

扩展成绩来源包括官方最近通过成绩、置顶成绩，以及本地 osu!stable 的 scores.db。先按被分析玩家的数字用户 ID，从 osu! 官方 API 取得该用户的现用名及曾用名名单。本地成绩中的玩家名必须与其中一个名字相同（不区分大小写，不使用模糊匹配）；若成绩另带数字用户 ID，也必须一致。玩家对比时，两位玩家各自匹配各自的名单，不使用当前登录者的名字代替目标玩家。

scores.db 通常只记录玩家名，不包含数字用户 ID，因此不能直接从该文件验证账号 ID；这里使用该 ID 对应的官方现用名／曾用名作为匹配依据，不把谱面 ID 或在线成绩 ID 当作用户 ID。随后还会核对键数、文件校验值及 Loved / Graveyard 状态。Pending / WIP、未提交、版本不符或无法确认的谱面不进入额外样本。没有匹配成绩的图不计算难度、不参与分析。

候选成绩先在本机用 rosu-pp-js 4.0.1，依据实际判定数、客户端和 Mod 复算官方 mania PP 公式，按复算 PP 降序选取额外 50 张；同一谱面的多条成绩只保留 PP 最高的一条。选取后才运行所选的能力算法，最多为 B50 加额外 50 张。不按星数、原始分数或假设满准度排序；缺少判定数的成绩不会模拟补齐。

坟图 / Loved 的复算 PP 是个人分析用参考值，不是官方授予的排名 PP，不会写入账号总 PP。基础指标仍是 B50 的统计。官方未提供的曾用名、未保存在本地的历史成绩、lazer 专用数据库以及官方最近列表之外的记录可能无法匹配。只有 Songs 而没有成绩库时，仅能补充已经找到官方实际成绩的本地谱面。

此前已绑定的目录需点击一次“重新扫描 / 授权”，以更新用于 PP 计算的判定字段；在重新扫描完成前，使用 B50。

BP 分析和玩家对比提供“能力算法”选项，默认“局部分段＋单项校准（试用）”；可选择“旧版 Mixed + Pattern”并重新分析以对照。浏览器保存该选择；运行中切换对下一次分析生效，对比双方使用同一选项。旧算法已在项目内存档，原有引擎与聚合模块保留。

常规段位与面条段位以两张独立卡片放在玩家资料下方、基础统计之前，无需展开详细情况；试用和旧版均使用此布局。“全部”键数按各键数分别列出。细分键型放在各项能力分析中，没有可用面条样本时主卡片明确显示暂无可用成绩。

分段试用结合 ManiaLiveDan 的 Sunny 局部 RC / LN 计算、自动分段与 LeoBlack Pattern 时间区间，额外按主导键型变化补充分段。切片保留跨界完整 LN 与 Timing Points，并使用整图长度因子。结果中的“局部谱面参考”描述谱面要求，不代表玩家该段的实际准确率；展开“局部谱面难度”可查看前 20 张已分析谱面的分段时间、RC / LN 参考、键型覆盖率及 LN 音符占比。多个键型可以重叠，覆盖率不要求合计为 100%。

主段位保留 v2 评分，不再使用 80% 覆盖率及准确率最坏下界作为评级门槛。每张有效成绩先用 Mixed 整图常规 / 面条等级作为标尺，再根据该键型所覆盖局部难度的分布进行有限修正：相对整图 Sunny 刻度最多上调半级、下调一级。覆盖率按属于该键型的不重复头部音符计算，多个键型可各有 60% 覆盖，不按总和重新归一化。

覆盖达到 50% 不扣覆盖档位，低于 50% 按 2 × log₂(0.5 / 覆盖率) 级扣减，同时降低单图参考权重；参考权重在覆盖 60% 时达到满额。常规以 96%、4K 面条以 97%、7K 面条以 95%、6K 面条以 96% 为基准，整图 Acc 每低 1 个百分点暂降一级，高于基准不额外提级。这些是本站试用经验参数，不是经过回放验证的真实局部成绩，也不是数学意义上的能力下限。例如在局部相对难度相当时，Alpha / LN11 的图打出 96%，单乱与面切各覆盖 60%，单图可估为 Alpha 单乱、LN10 面切；20% 的叠不会同样获得 Alpha。

同一谱面最多计一条最强贡献，对最高五张贡献按覆盖率、短段可靠度及顺位加权汇总。少于 30 个音符、4 秒的样本降低权重；判定口径无法完全重算但有有效完整成绩时降权参考，不再将所有能力抹为“证据不足”。未完成、无实际成绩、无效判定或零准确率不评级。单图、多图和低覆盖情况会标明，所有能力显示“估计”；不同键数分开。疑似 Vibro 不计入普通键型评级。

名称按站长用语统一为常规、面条、单乱、协调、放手、盾、反键、四押切、对拍、纵叠、大叠、对切、锁手等，试用与旧版显示共用翻译。黄彩保留原值并分别展示 stable / lazer；仅画像“准度型”判断使用调整值，单图黄彩贡献封顶 1:1，lazer 以 stable 的 50% 权重计入，不因重新归一化抵消降权。此比例是本站试用参数，黄彩不直接提升键型等级，不修改成绩、Acc 或 PP。

单项校准 v3 只修改具体键型，常规与面条两张主段位卡片的计算保持原样。常规单项包含 LN 按下部分实际匹配的键型，以常规标尺估分；面条单项的频率改为在长条头部内计算。低频单项最多因占比扣一级，参考权重仍随全图覆盖、音符数量和时长下降，不从综合段位凭空生成未出现的键型。

常规单项的 Acc 缺口 d（百分点）扣 0.3d + 0.02d² 级；面条单项保留原准度处罚。Sunny LN 已包含长条区间中的普通音符；v3 进一步让同一匹配所在段的常规相对负担抵消部分 LN 局部低读，同时取消 LN 单项的普遍半级切片上调。不把常规与面条段位相加，也不从其他无该键型的段借难度。

本次用 MyAngelHyacine、ruhgss、CapooFanboy、[GB]fanqiu、Hanenya 的 250 张 B50 成绩作回归。与 Mania Tracker 对照时，其叠键／速度／技术是较宽类别，本站采用同类中最强已检出子项作粗粒度检查；LN 协调与 LN Technical 只作近似检查。本组对照差距不超过一级，不代表每个细分键型都与 Tracker 等价，也不保证其他玩家误差始终在一级内。Tracker 使用的更大成绩池与本站 B50 亦不同，未用姓名、谱面 ID 或 Tracker 在线结果直接决定本站分数。

每张谱面最终最多 10 段，优先合并相邻且难度相近的区间，再重算合并段；不再因分段超过 80 而整图跳过。细小变化可能合并在同一段内。Loved / 坟图仍按真实成绩复算 PP 后选前 50；网页已允许本地 PP WebAssembly 计算，模块初始化失败时会停止重复尝试并提示原因，状态查询失败、缺少匹配文件和无效判定分别报告。

试用支持 4K / 6K / 7K，单图最多 30000 音符、15 分钟，最终最多 10 段，后台单图 45 秒超时；超限或失败明确跳过。EZ / HR / DA 等改变 OD 的 Mod 暂不参加试用结构分析。局部 Sunny 仍可能受到同段其他键型影响，不能视为独立技能测量或正式段位认证。

旧版下载完整 .osu 后计算 Mixed 难度与 Pattern 键型特征，再结合整图成绩生成 RC / LN 倾向和各项能力，保留原来的计算和显示方式用于对照。

  • 当前未接入 Companella 的 ONNX 推理；需要相关模型时使用已有回退路径，不能视为完整上游实现。
  • stable 的 LN 成绩使用原始准确率，尚未加入 ScoreV2 尾判修正，LN 结果存在偏差。
  • 部分特殊 Mod（包括 RD、HO、IN 与键数转换）不参与结构能力分析。
  • 其他主模式目前提供基础成绩统计，结构能力算法尚未接入。“暂无算法”代表尚无支持，不代表玩家能力为零。
  • 能力值属于模型估计，样本数、键数、Mod 与成绩准确率都会影响结果，不等同于官方评级或段位认证。

首页管理

管理员登录后可在首页打开“管理首页”，修改全局标题、图片标题、超链接、顺序和轮播间隔。支持 1–20 张图片，切换间隔为 3–15 秒。

导入 osu! 谱面或谱包链接可获取曲绘，并自动填入“作者 — 曲名”和官网超链接，之后仍可编辑。也可上传不超过 2 MB 的 JPG、PNG 或 WebP。超链接支持 HTTP(S)，留空时图片不可点击。

仅站长 MyAngelHyacine（osu! ID：35851725）可以授予或撤销其他管理员权限。其他管理员可管理首页内容。

本地目录与数据

展开“本地 osu! 文件夹”，点击“浏览并绑定文件夹”。建议选择 osu!stable 安装目录，以便同时找到 Songs、osu!.db（谱面状态）和 scores.db（本地成绩）。在已授权目录中优先寻找 osu/Songs、osu!/Songs、Songs，也可直接选择 Songs。自定义子目录可手动填写；完整路径需粘贴到系统目录选择器地址栏，网站不能仅凭绝对路径读取磁盘。

目录索引与校验在浏览器后台进行，仅索引 .osu 及必要的本地数据库，不读取音频、视频或曲绘。每张 .osu 最大 2 MB；索引读取文件用于版本匹配，并不运行难度算法。只有存在匹配成绩时才执行难度计算。

本地 .osu 原文与成绩库不上传服务器。Chrome / Edge 可在浏览器本地保存目录句柄、索引和成绩数据，后续可能需要重新授权；不支持目录授权的浏览器使用文件夹选择，本次页面有效，跳转后可能需要重新选择。“重新扫描 / 授权”可刷新文件变化；“解除绑定”会清除本站保存的本地索引与成绩。

确认本地成绩的官方谱面状态时，仅向服务器发送谱面 ID。Loved / 坟图参与分析的前提是本地文件可读取且匹配到玩家成绩。坟图、Pending / WIP、未提交或未确认状态的 .osu 不在服务器下载或保存；其他已验证状态的官方谱面仍可使用原有持久缓存。

OAuth 凭据保存在服务器端，浏览器使用安全会话 Cookie；会话最长保留 30 天，可退出登录。BP 结果有 15 分钟缓存，刚更新的成绩可能不会立即显示。官方谱面持久缓存受托管配额限制，暂时无法保存不会阻止当前分析。
